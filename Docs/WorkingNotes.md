# 沟通理解与当前方向

修改前先读本文。每轮对话将新要求归纳到共同方向，用实际代码和验证校正判断；保留设计取舍，具体规范见 [ProjectGuidelines](ProjectGuidelines/AGENTS.md)，实现入口见 [ProjectTour](ProjectTour.md)，验证见 [Validation](Validation.md)。

## 核心意图

用户需要从代码直接看清职责、所有权和执行路径，便于学习和继续开发。扩展性来自正确的归属：共享数据在 Model，规则在 System，节点和表现归 Entity/Controller，具体角色的特殊行为归其技能和身体状态。每个实例的输入消费、物理事实和局部计时保留在对应运行实例。

借鉴成熟项目要落实到实际用例，并理解其取舍。不能因为 QF 有某个机制就全量照搬，也不能以“少封装”为由拒绝有实际职责的 Command/Query。用户纠正的是过度机制和错误归属，架构整理仍需继续完成。

## GGF + QF 的取舍

GGF 主流程 FSM 的 GetData/SetData 是唯一注册位置，Architecture 只是按类型访问视图；Get 返回同一引用。Procedure 装配和结束应用、档案、本局作用域；依赖先注册，清理逆序执行。Model 不拥有节点，Entity 借用已创建的数据。

Controller 可以直接读 Model/System、注册绑定。玩家穿戴、卸下、出售和学习经 Command 调用 System；System 执行规则及写入。窗口分页、悬停、tooltip、关闭由窗口处理，导航由 Procedure 处理；具体动作、物理和业务推进仍由状态、Entity、System 协作。

Query 负责一次组合读取，已用于整包出售件数和总价；简单字段直接 Get。Bindable 和事件观察后续变化，需要时重新执行查询。提交 Command 时仍根据最新状态校验，不能把查询结果当成交易承诺。

以 QF 官方源码和教程校正借鉴范围：Query 可选，不要求所有读取经过 Query；取得 Model/System 的接口不会强制返回只读对象。需要明确调用纪律和实际归属，而不是增加只读模型副本或查询绑定层。现有五类界面业务请求已走 Command，本轮复核通过原有 170 项档案、命令、查询和绑定测试，补清规范与代码契约，保持现有运行逻辑。

绑定容器保持普通独立对象；拒绝 CreateProperty/CreateList、BeginUpdate/Dispatch、NotifyValueChanged、ModelUpdate/UpdateScope、额外 BindableEvent 和共同 ArchitectureMember 基类。关联显示提交完整值，不靠延迟通知维持表面一致；接口划分取用能力，读写按职责约定。

## 技能、输入与动画

执行路径为“原生 Input 查询 → 本角色消费记录 → 角色匹配 → SkillSystem 校验扣费 → 具体 GGF 状态 → 节点表现”。SkillModel 只保存技能书；当前登记、激活编号和无敌区间归本局 HeroModel。状态应读得到完整招式行为与阶段，共享层不承担悟空例外；新增角色无需扩展固定三键输入或统一动作解释器。

原生 AnimationPlayer 管时点、属性和判定几何，动画回调用 AnimEvent 后缀；具体状态管输入窗口、分支、运动、中断和清理。使用原生标记分段时，起点方法键须由原生 Seek 显式求值；不以超时掩盖招式未完成。独立效果自己拥有命中预算和池生命周期。

数值表保存费用、伤害、成长、掉落和关卡配方；缩放、偏移、镜像、声音时点和视觉编排归场景/动画。判断依据是策划能否在正确工具中预览并完成修改。装备身体和武器保持两套独立层，美术原点对齐规则；仅去除不适配其他武器的金箍棒形状残影。

碰撞表达玩法区域，不是复制美术轮廓。优先一两个矩形、圆或胶囊，允许有效攻击内部的透明间隙，排除纯装饰和大块外侧空气。精细 alpha 多边形即使能通过像素测试，也违背可编辑、可理解和数量少的目标；应删除这种机制及相应测试。地形保留简单整体坡体，避免为追求基础体数量形式而拆出更多重叠块和接缝。

## 阅读和资源组织

先确认类型有无独立职责，再命名或拆文件。小配套类型随主类，完整区域用 Panel，布局容器不用专门脚本。FormData 是窗口参数契约，需要参数的窗口保留，即使只有一个引用；只有重复编号的运行时空壳可以删。

改名贯通类型、字段、参数、目录、表和调用；持有单份数据用 m_EquipmentData，集合用 EquipmentDatas。GGF 窗口统一 Form，内部区用 Panel、Bar；场景 snake_case，保留 UID。

视觉清理核对完整层级和装饰职责。左下角保留造三法宝、宠物、技能、背包、设置五入口与无双黑色长底板；技能和无双使用约定的造一资源。图标贴地只调整显示原点，拾取仍用固定碰撞盒。

## 验证与工作边界

生产 API 服务游戏消费者，测试用现有 FSM、节点和反射观测，不添加状态名 getter 或故障注入开关。夹具应适配唯一模型引用，不能为旧测试恢复数据副本。异步等待捕获所属周期引用和取消令牌，迟到实体由原服务回收；初始化失败也要清理已取得资源。

框架、插件、生成物、旧工程的边界见第 50 章；旧存档只做获准的一次性转存，正式代码只接受当前版本。保留 Git 索引，在隔离工程和隔离存档验证，区分断言、退出码、预期故障和既有依赖错误。
