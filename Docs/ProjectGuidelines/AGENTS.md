## 适用与裁决

- 适用于整个仓库。任务先读本索引，再读涉及的模块；涉及 GGF API 时查 `Godot/docs/` 并核对代码。
- 用户当前指令优先。规范与实现冲突时报告，不以 AI 推断改写规范；旧项目只作只读参考。
- `Framework/`、`addons/`、`Tools/Luban/`、生成代码/资源和旧项目为只读边界。Claude 配置（`Godot/CLAUDE.md`、`Godot/.claude/`）是非权威工具参考，不覆盖本目录规范。
- 项目规范按用户明确要求维护。更新时修改对应模块，检查交叉引用与重复规则；目录级 `AGENTS.md` 只保留指向本索引/章节的导航。
- 交付说明改动、规范依据、验证命令和结果、未完成项；不声称未运行的验证已通过。

## AI 工作方式

- 修改前先读 [沟通理解与当前方向](../WorkingNotes.md)。每轮交流后分析其核心意图及与既有要求的共同方向，把新形成的理解、设计取舍和实际进度维护到该文档，不逐条照抄或重复记账。该文档记录用户意图，不取代本目录规范。
- 本项目采用 [Stop That Shit 0.2.5](https://github.com/lennney/stop-that-shit/blob/0.2.5/skills/stop-that-shit/SKILL.md) 的 Stop Ladder 作为工程决策规范，与上述 Godot / GGF / QF 模块规范共同执行：
  1. 明确当前交付、授权边界及已有保证，查清受影响的调用与失败路径；必要的调用方、数据、测试和文档一并完成，不以更容易通过的子集代替交付。
  2. 从项目已有实现、标准库、Godot 原生能力及已安装依赖中选择直接方案，核对真实行为与生命周期；调查范围与任务相称。
  3. 只有具体输入、消费者、故障或既有支持承诺存在缺口时才增加机制；不为假设中的未来扩展复杂度。
  4. 保护措施须说明检测对象及拒绝、恢复或诊断的实际作用。保留有效保护；用途不明先查调用链，不凭名字或行数删除；修正吞错、重复副作用及阻碍正常行为的保护。
  5. 按项目要求验证受影响行为，复用对当前最终状态仍有效的证据；交付完整、必要验证充分且无范围内阻塞后结束，不无故重复审查、测试或增加审查代理。
- `review`、`answer`、`monitor` 默认只读；`change` 只允许已授权工作和必要连带修改。普通实现选择从已有上下文解决，不重复索取授权；缺失信息会实质改变结果、边界或难以撤销的选择时才询问。
- 不为执行 Stop Ladder 新建清单、证明文件或代理流程。交付说明结果、相关验证及影响使用的限制，避免重复过程说明。插件安装与 Hook 生效边界见 [50](50-FrameworkAndTools.md#stop-that-shit)。
