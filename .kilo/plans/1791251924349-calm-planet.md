# UI 数据绑定框架方案（定稿）

## 目标
用 **GGF 管窗口 + QFramework `BindableProperty` 管状态 + `GF.Event` 管业务事件**，建立可读、可扩展的 UI 数据流，终结“事件乱飞”。
范围：先服务战斗 HUD（血量/等级/无双/Go），并为唐僧（远程）、八戒、沙僧（双武器）、双人模式预留。

## 用户已确认的三项决策
1. 英雄数值真源：**引入 `PlayerRuntimeState` 作为真源**（HP/无双/等级写入 Model，实体与 HUD 共用）。
2. 存档：**本轮接入 `GameSession` + GGF `Archive`**。
3. 怪物血量：**只英雄 Model 化**，怪物继续用实体 HP。

## 架构总览
```
[配置/存档]  GameData(Archive) ──┐
                                 ├─> GameSession ──> PlayerRuntimeState (Model, BindableProperty)
[HeroConfig] ────────────────────┘                        │  只读接口 + 业务方法(TakeDamage/Heal/AddExp…)
                                                          │
        HeroEntity ──写──> PlayerRuntimeState <──订阅── BattleHud (GGF IUIForm)
              └─ 只读(战斗属性/表现)                 └─ 子控件 HealthBar / ExperienceBar
```
- **数据与节点分离**：`PlayerRuntimeState` 是英雄数值真源；`HeroEntity` 只写不缓存；`BattleHud` 只读订阅。
- **一次整体通知**：等级/经验/经验上限变化发 `ProgressionChanged`，避免读到不一致快照。
- 不做完整 MVC：仅引入状态通知能力（符合 `Docs/gpt-1.md` 结论）；复杂页面（角色详情等）将来再抽 Presenter。

## 规则（写入规范）
| 内容 | 通知方式 |
| --- | --- |
| 血量/魔法/经验/金币/无双（连续值） | `BindableProperty`，UI 订阅属性实例 |
| 等级+经验+上限（需一致） | 一次 `ProgressionChanged`（不可变快照） |
| 死亡、升级、奖励、清波（一次性/跨模块） | `GF.Event` 业务事件 |
| 按钮/按键 | Godot 信号 → 业务方法 |

- UI 只读订阅，写入只走业务方法（`TakeDamage/Heal/AddExperience/AddGold`），不绕过结算。
- 订阅在 GGF `OnOpen` 建立、`OnClose` 用**绑定袋**集中释放（窗口可能回池复用，不能只靠节点销毁）。

## 事件收敛
| 现状 | 目标 |
| --- | --- |
| `ActorEntity.StatsChanged`（无参，全量重读） | 删除；改 `PlayerRuntimeState.Hp/WsValue/Progression` |
| `LevelController.TravelHintChanged(Action<bool>)` | `LevelRuntimeState.TravelAvailable`（BindableProperty<bool>） |
| `Completed/Failed/StageCleared/SpawnFailed/RightBoundaryReached/Activated` | 保留为一次性业务事件 |
| `GF.Event` `DamageDealt/MonsterDied` | 保留（业务事件，飘字/结算） |

## 关键实现点
1. **`BindableProperty<T>` 裁剪**：保留 `Value`（相等不通知）、`SetValueWithoutEvent`、`Register/RegisterWithInitValue/UnRegister`；删掉 `UnRegisterTrigger : MonoBehaviour`、`ComparerAutoRegister` 的 Unity 特性、`OrEvent`（可选）。
2. **`BindingBag`**：`Add(IUnRegister)` + `UnRegisterAll()`；HUD 用一个字段管理全部订阅。
3. **`ActorEntity` HP 钩子**：`ReceiveHit` 用 `ApplyDamage(damage)`，`Heal` 用 `ApplyHeal(amount)`；`Dead` 仍由实体维护（表现/身体状态用）。英雄覆写钩子写 Model，`Hp/MaxHp` 读 Model。
4. **`GameSession`**：`StartAsync()` → `GF.Archive.LoadAsync()`（无档自动新建）→ 校验 `CurrentData` → `new PlayerRuntimeState(data.Player, maxHp)`；`SaveAsync()` → 导出 `ToSaveData()` 后 `OverWriteAsync()`。
5. **HUD 绑定**：`OnOpen` 取 `PlayerRuntimeState`，`Hp/WsValue` 用 `RegisterWithInitValue` 立即刷新；残影血条用 Tween；`OnClose` `m_Bindings.UnRegisterAll()`。
6. **Go**：`LevelRuntimeState.TravelAvailable` 由 `LevelController` 写入，HUD 订阅（替代 `TravelHintChanged`）。

## 分阶段
1. **绑定内核**：vendored `BindableProperty` + `BindingBag`；单测。
2. **玩家 Model + 存档**：`PlayerSaveData`/`PlayerRuntimeState`/`GameSession` + `GameData.Player`；`ProcedureGame` 接线。
3. **实体接线**：`ActorEntity` 钩子 + `HeroEntity` 读写 Model；HUD 改订阅 Model。
4. **子控件与关卡状态**：`HealthBar`/`ExperienceBar`；`LevelRuntimeState.TravelAvailable`；点亮 MP/经验条（有数据后）。
5. **文档同步** + 回归。

## 验证
- **单测**（`Tests/BattleTests`，纯 C#）：`BindableProperty`（相等不通知、`RegisterWithInitValue` 立即回调一次、释放后不再回调、`SetValueWithoutEvent` 不通知）；`PlayerRuntimeState`（`TakeDamage/AddExperience` 通知次数与快照一致、`ToSaveData` 往返）。
- **Godot**：HUD 探针（打开绑定初值、受伤后血条/无双刷新、`TravelAvailable` 切换 Go、关闭退订无回调）；`--smoketest=level`/`ai`/`level-cancel` 回归；一次正常启动确认存档读写无错。
- **构建**：`dotnet build` + 两个测试项目全绿。

## 风险与注意
- `ActorEntity` HP 改 `virtual` + 钩子属**战斗核心路径**，改动集中在 `ReceiveHit/Heal/OnShow`，需回归怪物（猴子/妖猴）行为不变。
- `BindableProperty.Comparer` 是**静态字段**（按泛型类型），默认 `Equals` 足够；如需自定义需显式设置。
- 首次 `LoadAsync()` 会新建存档并写盘，属预期。
- vendored 代码保留 QFramework MIT 署名。
